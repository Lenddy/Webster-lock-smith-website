Two separate things here — let's take them in order.
1. Why it's stuck at the bottom instead of centered
Looking at your CSS, .modal-container is already set up correctly to center its child:
css.modal-container {
	position: fixed;
	inset: 0;
	display: flex;
	align-items: center;
	justify-content: center;
	...
}

position: fixed + inset: 0 + flex centering should center the modal in the viewport regardless of where <Modal /> sits in your component tree. So if it's actually showing at the bottom, the classic cause is: some ancestor element has a transform, filter, perspective, or will-change property set on it.
This matters because position: fixed is normally relative to the viewport — but the CSS spec says if any ancestor has one of those properties, that ancestor becomes the new positioning context instead of the viewport. So instead of centering in the whole screen, your modal ends up centering (or getting pushed) relative to that ancestor's box — which, if that ancestor is short or scrolled, can visually look like it's glued to the bottom.
Since <Modal /> renders inside <Footer /> here, check:

Does .footer-container or any parent (App wrapper, page transition wrapper, etc.) have transform, filter, or will-change anywhere in its CSS or inline styles?
Any animation library (Framer Motion, etc.) applying a transform to a layout wrapper?

The fix, if you find one, is usually to render the modal via a portal (createPortal into document.body) so it's never nested inside a transformed ancestor in the first place — that's the standard, most robust fix for this exact bug, more reliable than hunting down every transform in the app:
jsximport { createPortal } from "react-dom";

const Modal = ({ isOpen, onClose, data }) => {
	return createPortal(
		<div className="modal-container" onClick={onClose}>
			{/* ...rest unchanged... */}
		</div>,
		document.body
	);
};
This guarantees .modal-container's position: fixed is always relative to the real viewport, no matter what wraps it in the component tree.

Comparing against your actual JSX, only these classes are used: modal-container, modal-wrapper, modal-header, modal-close, modal-content-header, modal-content-top-info-title-wrapper, modal-content, modal-bottom, model-bottom-wrapper. Everything else (door-handing, modal-content-info*, modal-content-middle-info*, modal-content-bottom-info*, model-btn-view/update/delete, modal-content-item-info*) looks like leftover cruft from a different modal (the "Material Request" one referenced in your comments) and isn't referenced anywhere in this file.
